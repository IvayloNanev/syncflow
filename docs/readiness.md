# Request status and readiness

Status and next action are calculated on the server from saved request facts, current analysis and reviewer tracking. States include Needs analysis, Recording unresolved, Recording mismatch, Needs clarification, Needs fact confirmation, Ready for internal review, Internal review pending, Changes requested, Declined, Ready to complete internal review and Internal review complete.

The completion command rechecks all prerequisites in a transaction: exact recording consistent with confirmed artist/title/version, twelve confirmed checklist fields, a current successful analysis with no checklist issues, and at least one reviewer with all assigned reviewers currently Approved. Client/agent supplied approval flags are rejected. Expected request revision and reviewer version prevent races. Command replay is idempotent. A separate additive SQLite table preserves human completion records and history without modifying facts or invalidating current analysis.

A completion only counts for the request revision and reviewer version it records. Later changes make it outdated and all gates must be satisfied again. The prototype conservatively requires every field and treats all assigned reviewers as required; justified N/A fields and optional reviewers are not supported. These are prototype assumptions, not Warner policy. Internal-review readiness is not rights clearance: catalog ownership checks and the licensing process remain separate.

Validation: 173 tests passed; lint, TypeScript and production build passed. Browser walkthrough confirmed ten remaining facts against source-backed proposals, refreshed the checklist, verified completion disabled while old reviewer approval was stale, manually reconfirmed a fictional reviewer, then recorded completion. Status, attribution and completion history were shown and retained on reopen. Tests cover missing/current analysis, incomplete facts, recording identity, pending/declined/changes-requested/stale reviewers, old completion snapshots, ownership and API bypass rejection.

Recording correction follow-up: 193 tests pass. Confirmed identity mismatches block readiness; corrections preserve messages/facts and make dependent work outdated. See [Recording corrections](recording-correction.md).
