# Email forwarding

Forwarding uses Resend Receiving and its free account receiving domain. No sending is enabled. Set server-only `RESEND_INBOUND_API_KEY`, `RESEND_INBOUND_WEBHOOK_SECRET` and `SYNCFLOW_INBOUND_DOMAIN` (domain only). Configure a Resend webhook for `email.received` at `https://<app-origin>/api/webhooks/resend`. Keep secrets out of browser variables and source control.

Apply `db/email-forwarding.sql` and `db/email-inquiries.sql` before enabling the handler. Routes and receipts are server-only under RLS. The commit RPC checks current membership and the forwarding account's confirmed email, commits the domain request and delivery receipt together, and rejects stale writes. Provider retries deduplicate by received email ID. Request-specific addresses preserve case identity rather than guessing from subject lines.

In **New Inquiries**, new external emails are stored as inquiries, without creating cases or calling an agent. Review the preserved email, then select **Save as a case**. The save commits the case, receipt and inquiry link atomically; repeated saves return the existing case. Saved inquiries leave the pending inbox and appear in Cases. A pasted email can also be saved directly as a case; the page stays in New Inquiries and displays a glass confirmation overlay: **Inquiry is saved in Cases.** Subject and Body have separate fields. Agent analysis begins only when the saved case is opened in Coordinator. Case-specific forwarding routes retain their existing coordinator sender restriction and append replies to the chosen case.

The November 10 storage change also stages deliveries from the previously deployed webhook handler. Its existing commit RPC now captures new-email inquiries instead of creating cases. Existing cases and receipts are preserved. Inbox and save UI changes are in the current checkout; they have not been deployed as part of this change.

This first version imports plain text, including any forwarded headers/quoted history supplied by the email client. It does not infer the original sender from the forwarded body or strip quoted material. HTML-only, empty and oversized messages are not imported. Attachments are not downloaded; an attachment warning is saved with supported messages. Resend delivery logs expose permanent rejection (`Not imported`) versus temporary retry failures. No in-app rejected-delivery inbox exists yet.

Treat forwarding addresses as private write-capability addresses. Exact outer From matching is an additional allowlist, not cryptographic sender authentication. Webhook signatures authenticate Resend delivery; they do not prove that an email From address cannot be spoofed. No case content is disclosed by the webhook. Revoke routes server-side by setting `enabled=false` if an address is exposed; a self-service rotation UI is not yet included.
