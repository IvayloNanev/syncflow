# Durable analysis failure recovery

This increment replaces the generic stored failure with a fixed allowlisted reason and optional safe validation categories. Messages are chosen by application code; raw provider bodies, rejected payloads, schema errors containing quotes and arbitrary diagnostic text are not persisted or sent to the browser. Older saved failures remain generic because missing historical information cannot be recovered.

The workspace presents the last attempt's state, source revision and support reference. A read-only status check reloads persisted state without generating. A manual retry gets a new command key; ordinary command replay remains idempotent. For running attempts the new-attempt action appears only after a successful check and an age over 90 seconds. This client guard is a usability limit, not a distributed job lease: the local server rejects overlapping analyses and the existing newest-run/revision activation guards protect against late results. Durable job queues/worker leases for production remain future infrastructure work.

No automatic retries were added, and all output validation stays strict. Confirmed fields, messages and saved reports remain unchanged on failure. An earlier validated same-revision result remains active rather than being overwritten by invalid output; the recovery panel explicitly explains that the earlier result is shown.

Validation: 188 tests passed, including a new safe-failure vocabulary test, valid-result preservation plus explicit retry recovery, and browser-API history/replay checks. Read-only checks and replay made no extra provider calls in tests. Private canary text was absent from returned failures. Lint and production build passed. Faults were injected into isolated temporary/in-memory test stores, not the user's working browser database. The failure-panel visual state was not exercised with a forced live provider outage, and the original historical E11 rejection remains undiagnosed.
