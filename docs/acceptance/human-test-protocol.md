# Human usability and timing protocol — pending execution

No participant results or preparation-time savings have been measured in this protocol. Automated test timings and model latency must not be used as a substitute.

## Participants and method

Use a person unfamiliar with SyncFlow for an uncoached usability session. Use a coordinator or an explicitly labeled student proxy for the paired timing study. Record participant role and familiarity; student results do not establish benefits for Warner staff. Use fictional requests only.

For each timing pair, prepare two equivalent but different emails with a written answer key. Counterbalance manual-first and assisted-first across five pairs. Manual work uses the email and a blank tracker; assisted work uses SyncFlow. Both include reading, identifying the recording/version, resolving gaps, checking extracted facts and producing the next-step draft/handoff. Stop at the same output, not at the first model response. Record errors and corrections as well as time; do not discard slower or failed attempts.

## Five paired scenarios

1. Complete campaign request: original Northern Lights by Maya Rivers, Canada, YouTube/Instagram, six months, 30 seconds, CAD 5,000 for both rights; explicit project/contact and dated deadline with time/timezone.
2. Incomplete request: instrumental version, missing platforms/music length/project/deadline. Expected clarification asks only those details.
3. Ambiguous recording: Northern Lights without artist or version. Expected unresolved identity, no silent arbitrary selection.
4. Contradictory territory: Canada in one sentence and US-only elsewhere with no explicit correction. Expected clarification, no inferred resolution.
5. Changed scope reply: Canada was confirmed and reviewed; a reply changes to worldwide. Expected proposal, preserved prior value until confirmation, stale approvals/completion and handoff visible.

Give an explicit answer key for every field/issue before collecting results. Ensure date/time/timezone policy matches the current checklist. Freeze the keys; do not change them to match an output.

## Uncoached usability tasks

- Start a request and identify the matched recording/version.
- Distinguish provided details, unconfirmed facts and missing client answers.
- Draft a response, append a reply and recheck.
- Confirm source-backed facts; generate, edit, save and reopen a handoff.
- Assign a reviewer, record a decision, and explain why changed scope requires reconfirmation.
- Explain whether anything was sent and whether music rights are cleared.

Observer records task success, hesitation, wrong turns, recovery, any coaching and time. If coaching is required, mark the task coached; do not call it an unassisted pass. Note the default input-only start and dashboard entry discoverability.

## Targets and worksheet

PRD targets: at least 25% lower median paired preparation time including review; at least 95% extraction precision and recall; at least 90% issue recall and at most 10% false discovery against a frozen current-policy key. No silent overwrite, automatic sending or agent approval. These targets are not yet achieved merely because code tests pass.
